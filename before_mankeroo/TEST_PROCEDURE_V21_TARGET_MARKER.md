## 1. JHMCSのバグ修正について（即時修正・配備完了）

ご報告いただいたJHMCSの不具合：
1. **「表示されるべき状態でない要素まで全部表示される」**
2. **「味方（見方）が表示されなくなったりする」**

### 原因と修正内容
- **原因**: 以前の `ac8_m_jhmcs.lua` では、360°追従を維持する際に、ターゲットアクター配下の **全子コンポーネント（護衛アイコン、ピン矢印、HPゲージ、通信アイコン、ゲーマータグ等 11種類）を一律で強制可視化（`SetVisibility(true)`）** していました。
  - このため、敵機に護衛ダイヤやピンが全表示され、さらに味方機にも敵用四角枠が被さって味方表示が破壊されていました。
- **修正**: 子コンポーネントの一括強制表示ループを **完全撤廃** しました。
  - JHMCSは親アクター（`ChronicleTargetContainerActorBP_C`）のFOVカリング解除のみを行い、**「どのアイコン（四角枠／護衛／味方表示）を出すか」はゲーム本来の判定ロジックに100%委ねる** ように修正しました。
  - これにより、敵・味方本来の正しい表示状態が保たれたまま、360°全周で追従するようになります。

## 2. ターゲットアイコンサイズ変更：v21（ネイティブメモリ直接操作）

v20 で「全部変化なし（Case 4 の色変化もなし）」だった理由が、Unreal Engineのエンジン内部解析により判明しました：
- 四角枠のシェーダー（`M_HUD_TargetContainer3DUI_000`）はパラメータ化されていない固定シェーダーであり、外部からの変数変更を受け付けない設計でした。
- そして、Unreal Engineのビルボードレンダラー（`FMaterialBillboardSceneProxy`）が四角枠のサイズを決める要素は **唯一つ、メモリ内の `Elements[0].BaseSizeX` と `BaseSizeY` のみ** です。

### v21 の新手法
UEVRのネイティブメモリ操作機能（`read_qword`, `write_float`）を駆使し、**ゲームエンジンが四角枠を描画する直前のメモリ（Element 0 の BaseSizeX / BaseSizeY）に直接新しいサイズを書き込み、`MarkRenderStateDirty` で再描画を命令** します！

## 3. テスト手順（v21）

1. UEVRメニューを開き、**`Reset Scripts`** をクリックしてください。
2. UEVRメニュー内に **`AC8 Target Icon Scaler (v21 Native Memory)`** が表示されます。
3. 画面上に現在のメモリ検出値が表示されます：
   - `Elements Offset: 0x...`
   - `Current Memory BaseSize: (X=128.0, Y=128.0)`
4. **Case 1 のスライダーを動かして、四角枠のサイズが変化するか確認してください。**

| ケース番号 | 操作項目 | 内容 | リセット操作 |
| :--- | :--- | :--- | :--- |
| **Case 1** | `Native Icon Size (32~1024)` | メモリ内の BaseSizeX & BaseSizeY を直接書き換えて再描画（**256〜512** に動かす） | `[128 Reset]` |
| **Case 2** | `Screen Space Mode` (チェックボックス)| スクリーン固定ドット数 vs 3Dワールド空間サイズの切り替え | `[Default Reset]` |
| **Case 3** | `RelativeScale3D (1.0~50.0)` | トランスフォームスケール（初期値25.0）の上書きテスト | `[25.0 Reset]` |
