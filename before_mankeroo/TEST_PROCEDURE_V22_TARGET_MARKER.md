# AC8 JHMCS バグ修正 ＆ ターゲットアイコン Scaler v22 テスト手順書

## 1. 今回の修正・改善内容の要約

### ① JHMCS バグ修正 (`ac8_m_jhmcs.lua`)
- **原因の特定**:
  - ゲーム内にはターゲット枠アクター（`ChronicleTargetContainerActor`）が全マップで **4つのみプール（使い回し）** されています。
  - 敵機を撃墜した際、ゲーム本体は枠を非表示（`bHiddenInGame = true`）にして位置更新を止め、スロットを回収します。
  - 以前の JHMCS は全4枠に対して毎フレーム強制的に `SetActorHiddenInGame(false)` をかけていたため、**撃墜されて移動が停止した残骸座標の枠が消えずに空中に固定され**、さらに枠スロットが枯渇して**僚機（味方機）に枠が回らない**という2つの不具合が同時に発生していました。
- **解決策**:
  - 3次元ワールド移動速度（Movement Delta）を監視。
  - 飛翔中の航空機（時速 150 km/h 以上）のみ 360° JHMCS 追従表示。
  - 撃墜・停止した枠（速度 ≈ 0 km/h）は **即座に非表示化してゲーム本体の管理システムへ返却**。
  - これにより **「撃墜機の残留消滅」** と **「僚機（味方機）への枠即時割り当て」** を同時に実現しました。

### ② ターゲットアイコン Scaler v22 (`ac8_target_3d_test.lua`)
- **前回の問題点**:
  - v21 では UI 縦幅が狭く Case 2 / 3 が画面外に見切れていました。また UEVR Lua 1.05 環境でメモリ直接書き込み API が未バインドだったため Case 1 が無効でした。
- **v22 の改善**:
  - **画面見切れの完全解消**: 無駄なログ・警告表示を全撤去し、コンパクトに 3 つのケースが 1 画面に収まるよう設計。
  - **1 ケース = 1 スライダー/チェックボックス ＋ 1 リセットボタン**:
    - **Case 1**: `AddElement` ネイティブ置換（32.0 〜 512.0）
      - 元の 128x128 Element 0 のマテリアルを透明化し、指定サイズの新しい Billboard Element を描画。
    - **Case 2**: `RootComponent` 階層スケール（0.05 〜 1.00、初期値 0.20）
      - 枠と文字の親階層全体の 3D スケールを直接拡大縮小。
    - **Case 3**: スクリーン空間ピクセル固定モード切替（`bSizeIsInScreenSpace`）

## 2. テスト手順

### STEP 1: JHMCS の確認（飛行中）
1. ミッション（または訓練）で飛行を開始します。
2. **僚機（味方機）** の方向を向き、僚機アイコン（緑/青のひし形・文字）が正常に表示されるか確認します。
3. 敵機を1機撃墜し、撃墜後に視界外（横や後ろ）を向いて **「撃墜された残骸アイコンが空中に残らないこと」** を確認します。

### STEP 2: ターゲットアイコン Scaler v22 のテスト
Insert キーで UEVR メニューを開き、`AC8-Target-Icon-Scaler-v22` を開きます。

| テスト項目 | 操作内容 | 期待される変化 |
| :--- | :--- | :--- |
| **Case 1: Reticle Size** | スライダーを 32 〜 512 に動かす | 敵機・僚機のターゲット四角枠のサイズが直接拡大・縮小するか確認 |
| **Case 2: Root Hierarchy Scale** | スライダーを 0.05 〜 1.0 に動かす | ターゲット枠＋文字全体の 3D サイズが拡大・縮小するか確認 |
| **Case 3: Fixed Screen Pixels** | チェックボックスを切り替える | 遠距離でも枠サイズが固定ピクセルになるか、実距離スケールになるか確認 |

※ 各ケース確認後は、必ず右側の **[Reset]** または末尾の **[Reset All to Default]** を押してから次のケースをお試しください。
